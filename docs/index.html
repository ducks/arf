Agent Reasoning Format. Track what the agent thought, not just what it changed.

What is ARF?

ARF is a TOML schema plus a CLI for capturing an AI agent's reasoning alongside the commits it produces. Records live on an orphan arf git branch, so the reasoning travels with the repo but never pollutes main's history.

ARF gives you:

  • arf record - agents emit what / why / how / backup before and after significant work
  • arf why <file>:<line> - git blame, but for reasoning: resolve a line to the commit that wrote it and surface the matching records
  • arf export --format html - generate a static viewer of the whole trail
  • File-and-line anchoring so a record can scope itself to src/foo.rs:42-76 rather than the whole commit
  • An orphan-branch storage model so reasoning never touches your working tree

Install

cargo install arf-cli

Quick start

arf init
arf record \
  --what "Refactor auth middleware" \
  --why "Legal flagged session-token storage for compliance" \
  --file src/auth.rs:42-76
arf log
arf why src/auth.rs:55

The --file flag is what makes arf why work later: a record can scope itself to a path, a line, or a range, and lookups walk back via git blame to find the right commit.

The live trail

ARF dogfoods itself. The live trail is this repo's own ARF history rendered with arf export --format html - every commit grouped with the records that explain it, diffs inline.

Why this exists

Commit messages tell you what changed. PR descriptions tell you why the PR exists. Neither captures the moment-to-moment reasoning an agent uses while writing code - the rejected approaches, the constraints it weighed, the rollback plan it had in mind.

ARF is a place for that reasoning to live, anchored to the lines it produced, queryable later when a reviewer asks "why does this exist."
